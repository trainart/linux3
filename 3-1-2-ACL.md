## ACL (Access Control Lists) 

Linux filesystem permissions are today more than we might generally know.

Basically we know permissions for:
* **U**ser (or user owner)
* **G**roup (or owner group)
* **O**ther (everyone else)

which are:
* **R**ead 
* **W**rite 
* e**X**ecute 

Plus three other attributes SUID, SGID, Sticky Bit.

However modern Linux systems have possibility to use additional **ACL**s (**Access Control Lists**), 
which enable more flexible and granular control over access rights.

ACLs enable to set **additional** permissions for file/directory to individual users or groups
without changing the base ownership and permissions.

ACL is Linux kernel feature and is currently supported by many modern filesystems, including (but not limited to):
* **ext2**, **ext3**, **ext4** 
* **xfs**
* **tmpfs**
* **zfs**
* <br>
...


### Install ACL (if not present yet)

With ACL (Access Control Lists) it's possible to set access permission to files or directories more strictly than standard permissions.

> Key Concept: **ACLs OVERRIDE standard permissions!**

In recent Linux versions acl package is already installed.

You can check if it is there with:

```bash
rpm -q acl
```

If you get the package name, it means you have it installed.

If missing, it can be installed with:

```bash
yum -y install acl
```

There are two main commands for ACL management:

* **getfacl** - view ACLs 
* **setfacl** - modify ACLs

### Simple example

Create test directory 

```bash
mkdir /opt/acltest
```

Check initial state

```bash
getfacl /opt/acltest
```

Nothing special yet.

#### BTW 

> You may see message `getfacl: Removing leading '/' from absolute path names` <br>
> It is not problem (just for information), but can be annoying.<br>
> How to get rid of it ?
<br><br>


Now assign additional ACL to `student`
```bash
setfacl -m u:student:rwx /opt/acltest
```

Check now

```bash
getfacl /opt/acltest

```

You should see new line `user:student:rwx`

Now as user **student** create new directory inside `/opt/acltest/`

```bash
sudo -u student bash -c 'mkdir /opt/acltest/student-dir'
```

#### BTW

> You can also do the above with `su - student`.
> * What is the difference ?
> * Why do we use `bash -c` here ?  
<br><br>


Now check (you should notice additional "**+**" sign after `/opt/acltest/` permissions)

```bash
ls -la /opt 
```

<br><br>
> REMEMBER ! <br>
> `ls` shows `+` indicator where there is ACL <br>
> So if you see `+`, you might want additionally run <br>
> `getfacl` for that file/directory <br>
> to get REAL permissions picture.
<br><br>

Logically, you can see the same additional "**+**" sign inside the directory list - after `.`

```bash
ls -la /opt/acltest
```

Now as user **student** create new file inside `/opt/acltest/`

```bash
sudo -u student bash -c 'echo "Student file" > /opt/acltest/student-file'
```

Check

```bash
ls -la /opt/acltest 
```

### Removing ACLs

`-b` option removes all ACLs from file/directory

Run the following to remove all ACLs from `/opt/acltest`

```bash
setfacl -b /opt/acltest
```

Note `+` indicator has gone from directory `acltest`

```bash
ls -la /opt 
```

So user `student` don't have special permission inside `/opt/acltest` directory anymore.

Try as user **student** create new file inside `/opt/acltest/`

```bash
sudo -u student bash -c 'touch /opt/acltest/new-file'
```

But what belongs to the `student` remains.
For example, you can add data to the file `/opt/acltest/student-file`

```bash
sudo -u student bash -c 'echo "Hello"  >> /opt/acltest/student-file'
```


```bash
cat /opt/acltest/student-file
```

### Resume 

* ACLs allow granular permission control beyond traditional Unix/Linux permissions 
  * with ACL rules we provided separate additional permission to user `student` for directory `/opt/acltest/`
  without touching basic **R**ead, **W**rite, e**X**ecute permissons for **U**ser, **G**roup, **O**ther. 
* Combine `setfacl/getfacl` with traditional `chmod` for comprehensive security
* If you decide to use ACL, document details of your config, as they can become complex to manage

### Create additional ACL with `setfacl`

Try modifying some file <br> 
**as user `student`**

You should not be able to do so.

```bash
echo "Test" > /opt/project1/file7
```

```bash
setfacl -m u:student:w /opt/project1/file7
```

```bash
getfacl /opt/project1/file7
```

Notice added line `user:student:-w-`

Also notice we can see additional ACL are present with `ls -l` too:

```bash
ll /opt/project1/file7
```

NOTE: **[+] is added on attribute**

Now try again  <br> 
**as user `student`**, <br>
it should work now:

```bash
echo "Test1" > /opt/project1/file7
```

```bash
echo "Test2" >> /opt/project1/file7
```

At the same time if you try to **see/read** that file it will not work

```bash
cat /opt/project1/file7
```

Why ?

From the above `getfacl` output you may notice:

> `user:student:-w-` <br>
> ... <br>
> `other::r--`

We see that even though all others have **r**, student is specifically mentioned and has only `w`.
Thus permissions of user `student` should be mentioned separately.

Let's fix that.

We can remove all ACLs

```bash
setfacl -b /opt/project1/file7
```

And set new ones <br> 
(NOTE ! Previous removing was not necessary for this, just used to learn `-b` option).

```bash
setfacl -m u:student:rw /opt/project1/file7
```

```bash
getfacl /opt/project1/file7
```

Now try again to **read** that file <br> 
**as user `student`**, <br>
it should work now:

```bash
cat /opt/project1/file7
```

### Remove ACL

Let's new users and add ACLs for them to `/opt/project1/file7`

```bash
for i in 1 2 3 4 ; do useradd user$i ; echo -n "Created user$i. "; setfacl -m u:user$i:rw /opt/project1/file7 ; echo "Set ACL for user$i" ; done ;\
getfacl /opt/project1/file7

```
You should see ACL for both `student` and `user1`, `user2`, `user3`, `user4`

Now let's remove ACL for some of them and remove that users.

```bash
for i in 1 3 ; do setfacl -x u:user$i /opt/project1/file7 ; echo -n "Removed ACL for user$i. "; userdel -r user$i ; echo  "Deleted user$i";  done ;\
getfacl /opt/project1/file7

```

You should see only ACLs for `student` and `user2`, `user4`

## Mask

You may notice `mask` option in output of `getfacl`, what is it for?
(don't mix with `umask`, which is totally different thing).

**Mask** acts as additional/final global permission filter,
ensuring that users or groups **are not granted more permissions than allowed by the mask**.

So for all ACLs **MAXIMUM** of real/effective permissions will be what is allowed by mask
(NOTE! we talk about ACLs, **mask** is not related to basic **rwx** permissions for owner/group/others).

In case we don't specify the mask specifically it will be flexible to allow everything we specified for our ACLs.
But if we will specify that, access will be **not more than** allowed by mask.

If we will run 

```bash
getfacl /opt/project1/file7
```

we will see `mask::rw-`

But let's limit it manually

```bash
setfacl -m m::r /opt/project1/file7
```

```bash
getfacl /opt/project1/file7
```

> NOTICE  what added at the end of the line <br>
> `user:student:-w-		**#effective:---**` <br>
> it means that real permissions of `student` are nothing
> `user:user2:rw-		**#effective:r--**` <br>
> it means that real permissions of `user2` are now only `r`

Let's check if it is so.
As `user2`  run the following:

```bash
echo "Test3" >> /opt/project1/file7 ;\

```

You should get `Permission denied`.

Now let's fix the mask:

```bash
setfacl -m m::rw /opt/project1/file7
```

```bash
getfacl /opt/project1/file7
```

And try again as `user2` run the following:

```bash
echo "Test3" >> /opt/project1/file7
```

You also should be able to see the contents of `/opt/project1/file7`

```bash
cat /opt/project1/file7
```

But it will not be the same with `student`.

### ACLs for directories

Create another directory `/opt/project2`

```bash
mkdir /opt/project2
```

```bash
setfacl -R -m u:student:rwx /opt/project2
```

**-R** - sets ACL to a directory recursively 


```bash
getfacl /opt/project2
```

And now try as user **student** run the following:

```bash
mkdir /opt/project2/dirNEW
```

```bash
echo "TEST NEW" > /opt/project2/fileNEW
```

Check

```bash
ls -l /opt/project2
```
